# Skill Design Comparison — superpowers / dev-workflow-skills v1 / forge / foreman

调研对象 4 个 sibling 项目的 skill 设计对比，用于 dev-workflow-skills2 后续设计参考。

## Side-by-side Comparison

| 维度 | superpowers | dev-workflow-skills v1 | forge | foreman |
|---|---|---|---|---|
| **Project category** | General-purpose dev methodology plugin | Stage-based workflow skill pack | AI lifeform factory / control plane | 个人化 workflow architect agent |
| **Skill 总数** | 14 | 16 | 1 真实 SkillSpec（lifeforms/software-rd/skills/project-workflow.md）+ 多个 reference 到外部 | 11（含 2 deprecated alias） |
| **Skill 组织粒度** | Flat `skills/<name>/` | Flat `skills/<name>/` | `lifeforms/<lifeform-id>/skills/` 按 lifeform 隔离 | Flat `skills/<name>/` + project.yaml.skills 注册表 |
| **平均 SKILL.md 行数** | ~235 行 | ~115 行 | ~128 行（仅 1 个 sample） | ~240 行（最大 690） |

## 综合分析：哪些 pattern 应该借鉴 / 哪些应该避免

### 应该借鉴

1. **superpowers SessionStart bootstrap**：用 hook 一次性注入"必读 skill"内容，避免 always-on context burn 同时保证 LLM 看到 mandatory instruction。dev-workflow-skills v1 的"每个 skill 顶部写 First Step 期待 LLM 读"完全靠自觉，没有机械保证；foreman 用极长 description + audit-gate 兜底但 description 太长有 anti-pattern 风险。dev-workflow-skills2 应该效仿 superpowers 的 SessionStart hook 机制（前提是支持 plugin host）。

2. **foreman binary-enforced protocol**：`progress.py` + `audit.py` 把 prose 规则转成 exit code 是 4 个项目里最强的 enforcement。`per-target hash chain` 的 4 次失败演化（lock mtime → sha latest-only → 洗白漏洞 → hash chain）值得整段抄进 dev-workflow-skills2 的 audit-gate skill。

3. **forge canonical / projection separation**：SkillSpec 是 canonical，runtime/executor skill 是生成的 projection；projection 头写 `<!-- Generated by Forge. Do not edit as canonical source. -->` + manifest sha256 解决 "agent 改了运行时文件被覆盖" 的问题。dev-workflow-skills2 如果支持多 vendor 输出（不止 SKILL.md），应借鉴。

4. **dev-workflow-skills v1 path-key indirection** + **foreman dual-vendor symlink**：`paths.requirements` 等 logical key + symlink dual-vendor distribution，让 skill 跨项目复用且 vendor-neutral；dev-workflow-skills2 应延续。

5. **超低字数 description（superpowers）+ 23 skill 库**：超过 200 字的 description 容易让 LLM 把 description 当 workflow summary 跳过 skill body（`writing-skills/SKILL.md:158`）。23 个 skill 都做长 description 会爆 system prompt。建议每条 description ≤ 80 字，仅 trigger conditions。

6. **dev-workflow-skills v1 dashboard 写权限分层** + **foreman owner key marker `[owner:KEY]`**：把"谁能 advance stage"和"谁能改哪一行"显式机械化，dev-workflow-skills2 多 stage 协作时必备。

7. **forge workflow_spec as data**：lifeform.yaml `nodes.{name}.rules: when X then Y` 是真 condition rule。dev-workflow-skills2 7-stage workflow + 评审循环可以用类似 YAML / JSON 表达，runtime 直接读，避免 LLM 自由解释 workflow。

8. **superpowers writing-skills self-meta**：用 TDD-for-skills 方法论 (RED-GREEN-REFACTOR + pressure test with subagent) 反向开发 skill；dev-workflow-skills2 的 23 skill 库每个都应用这套方法测过。

9. **foreman scaffold-project B-i 复制式 distribution**：把 workflow-protocol skill 复制到新项目（而不是 reference）让新项目脱离原 skill 库后仍能运行；如果 dev-workflow-skills2 要支持"项目内嵌"模式，应借鉴。

10. **foreman Routine Audit Locality**：单 agent routine 收尾不被其他 owner 历史问题阻塞；dev-workflow-skills2 23 skill 多 agent 协作时极易出现"audit 全局健康检查导致单个 stage 永远 blocked"，必须有 locality 概念。

### 应该避免

1. **foreman 极长 SKILL.md（690 行）+ 极长 description（200+ 字）**：每次 invoke 都加载这么多 token；description 长到包含 workflow summary 反而触发 superpowers 论证的 "description 概括 workflow → Claude 跳过 skill body" 反 anti-pattern。dev-workflow-skills2 23 skill 应严格控制 SKILL.md ≤ 250 行 + description ≤ 80 字。

2. **dev-workflow-skills v1 "每 skill 顶部 prose First Step" 完全靠 LLM 自觉**：实测 LLM 经常跳过；foreman 已经用 binary 解决但代价是引入 `progress.py` / `audit.py` 等 dependencies。dev-workflow-skills2 应有机械保证，不能纯 prose discipline。

3. **dev-workflow-skills v1 角色名 (`requirements-analyst`/`tech-lead`)**：trigger discoverability 差，用户说"帮我写需求"LLM 不一定会优先匹配；foreman 的动词前缀 (`write-prd`/`review-prd`) 更好。23 个 skill 应统一用动词前缀。

4. **foreman `write-X / review-X` 1:1 重复**：每对 review skill 内容大量重复；dev-workflow-skills2 应考虑用 1 个 generic `cross-reviewer` skill 加 stage 参数化，或用 review-* skill 共享 references/。

5. **forge 概念过密** (lifeform / skill / workflow-spec / context-pack / runtime-instance / run-record / lifeform-design-session)：onboarding 很重；dev-workflow-skills2 应用最少新概念表达 7-stage workflow，避免引入 lifeform 这种产品级抽象。

6. **superpowers 没有项目状态管理**：对于"7-stage R&D workflow + 评审循环"是不可接受的——必须知道当前在哪个 stage、哪个 review 在 cycle 第几轮。dev-workflow-skills2 必须保留 progress.md + progress-history.md 机制。

7. **foreman deprecated alias skill 仍在仓库**：`write-feature-spec / review-feature-spec` 还占位；dev-workflow-skills2 应在 deprecate 时直接移除并在 changelog 记录，避免 LLM 误 invoke。

8. **dev-workflow-skills v1 完全没有 hook**：`completion-verifier` 是单点 stage gate 但 LLM 仍可以跳过；foreman 用 audit-gate binary 兜底解决；dev-workflow-skills2 应有兜底机制，不能纯 prose contract。

## 具体建议：给 dev-workflow-skills2 的 7-stage R&D workflow + 评审循环 + 23 skill 架构

### Skill 库整体设计

1. **Skill 命名**：23 个 skill 全部用**动词前缀**（`write-*` / `review-*` / `verify-*` / `audit-*` / `dispatch-*` / `merge-*` / etc.）；description ≤ 80 字仅 trigger conditions，**不写 workflow summary**；SKILL.md ≤ 250 行。
2. **Skill 文件结构**：`skills/<name>/SKILL.md` + 可选 `references/` + 可选 `scripts/`（必须可执行 binary）+ 可选 `templates/`；统一 frontmatter `name + version + description`。
3. **Vendor neutrality**：foreman 的 dual-vendor symlink (`.claude/skills/<name>` + `.agents/skills/<name>` → `../../skills/<name>`) + dev-workflow-skills v1 的 marketplace.json + plugin.json 三件套。

### Cross-cutting / 协议层

4. **`workflow-protocol` skill** (借鉴 v1 + foreman)：承载 startup checklist / progress hook / state machine / CR / cascade ≤ 2 / loop stop ≤ 7 / cross-review / dashboard 权限分层；vendor-neutral。
5. **`audit-gate` skill** (借鉴 foreman)：binary-enforced；至少 6 类 check（frontmatter / 状态机 / CR 引用 / progress 对齐 / git commit / baseline edit）；扩展时加 hash chain Check 7、lock Check 8；支持 Routine Audit Locality (`--owner-key`)。
6. **`scaffold-project` skill** (借鉴 foreman)：B-i 复制式 distribution，新项目自带 `workflow-protocol`；所有 23 skill 不全部复制，只复制 protocol。
7. **`session-bootstrap` hook** (借鉴 superpowers SessionStart) **+ 协议 cascade fallback** (借鉴 v1)：双保险——能用 hook 用 hook，hook 不可用时 skill 顶部"First Step"作为 prose fallback。

### State management

8. **progress.md / progress-history.md** (借鉴 v1 + foreman)：dashboard + append-only timeline；二者必须同 round 更新；通过 `scripts/progress.py` 唯一入口（foreman 风格）；Owner Key marker 隔离多 agent 写入。
9. **State machine 状态枚举** (借鉴 foreman)：`pending / draft / active / in-review / blocked / frozen / stable / completed / archived`；7-stage 中每个 stage 文档独立状态；advance 到 frozen/stable 必须经 audit-gate pre-freeze + human gate。
10. **Path-key indirection** (借鉴 v1)：`workflow-project.yaml` 含 `paths.requirements / paths.acceptance / paths.architecture / paths.progress / ...`；skill 通过 logical key 引用，禁止硬编码（`scripts/check-hardcoded-paths.sh`）。

### 7-stage workflow + 评审循环 mapping

| Stage | Author skill | Reviewer skill | 备注 |
|---|---|---|---|
| 1. requirements | `write-requirements` | `review-requirements` | 借鉴 foreman PRD + dev-workflow-skills v1 requirements-analyst |
| 2. acceptance | `write-acceptance` | `review-acceptance` | 借鉴 v1 acceptance-designer Variant A/B/C |
| 3. architecture | `write-architecture` | `review-architecture` | 借鉴 foreman write-architecture (C4 + ADR + Capability Registry) |
| 4. design | `write-design` | `review-design` | release plan + detailed design |
| 5. dev | `develop`（含 TDD discipline） | `review-code` | 借鉴 superpowers test-driven-development + subagent-driven-development |
| 6. test | `write-tests` | `review-tests` | E2E + automated setup |
| 7. delivery | `verify-delivery` | `audit-delivery` | 含 PASS/NOT PASS gate（v1 completion-verifier） |

23 skill 拆分建议：
- 7 stage author skill（write-*）
- 7 stage reviewer skill（review-*）
- 4 cross-cutting：`workflow-protocol`、`audit-gate`、`scaffold-project`、`session-bootstrap`（hook handler）
- 5 supporting：`workflow-router`（navigation only）、`parallel-dispatcher`、`git-manager`、`systematic-debugger`、`security-auditor`

如要精简到 23，可考虑：让 `review-*` skill 共享 references/（每个 review 仅一个简短 SKILL.md + 引用 `references/cross-review-template.md`）；或合并相邻 stage（如 design + dev 合一）。

### 反 anti-pattern 集合（必含）

- description ≤ 80 字，无 workflow summary
- SKILL.md ≤ 250 行
- 至少 1 个 binary 兜底（`progress.py` / `audit.py`）
- audit-gate 必须有 Routine Audit Locality
- review skill 必须 reviewer ≠ author（severity blocker/major/minor，conclusion binary pass/not pass）
- loop stop ≤ 7 轮
- CR cascade ≤ 2 stage（超出升 major change，human 决策）
- baseline 文档（frozen/stable）小调整必须经 audit-gate 代为执行
- 任何状态推进的 round 必须更新 progress dashboard + history
